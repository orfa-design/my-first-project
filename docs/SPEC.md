# Study Hub — специфікація

Персональний вебзастосунок для навчання в університеті на заочній формі. Інструмент для однієї
студентки, а не університетська LMS.

Мета — зменшити когнітивне навантаження: інформація, розкидана між Telegram, документами,
презентаціями та Google Drive, стає структурованою, пов'язаною та доступною для пошуку.

Критерій успіху: я передаю AI хаотичне повідомлення, файл, посилання або розклад — отримую
структуровані записи у Study Hub — і швидко бачу наступні заняття, що вже зроблено і що ще
потрібно закрити до сесії.

## Прийняті рішення

| Питання | Рішення |
| --- | --- |
| Як AI записує дані | Через Claude Code і CLI `npm run hub` (правила — `CLAUDE.md`). Вбудованого AI-чату немає. |
| Доступ AI до бази | CLI працює напряму з базою (`DATABASE_URL`) або через `POST /api/hub` з паролем `APP_PASSWORD` — у хмарних сесіях Claude Code прямого з'єднання з Postgres немає. MCP-сервер — пізніше, якщо знадобиться чат із телефона. |
| Історія змін | Не робимо. Натомість — поле «джерело» (`source_text`, `source_url`) і позначка `needs_review`. |
| Стек | Next.js 16 + TypeScript + Tailwind; PostgreSQL на Supabase; Vercel. Драйвер `postgres` без ORM — база доступна лише з сервера, тож RLS не потрібен. |
| Вхід | Один пароль (`APP_PASSWORD`), підписана ним cookie на 30 днів. Той самий пароль захищає `/api/hub`. |
| Мова, час | Інтерфейс українською, часовий пояс Europe/Kyiv. Дедлайн = дата + необов'язковий час. |
| Файли | У MVP лише посилання (Google Drive тощо), без завантаження. |
| Прогрес за предметами | Не показуємо у відсотках — без правил оцінювання це вигадана метрика. Показуємо кількість незавершених завдань і що чекає оцінки. |

### Статуси завдань

| Код | Назва | Значення |
| --- | --- | --- |
| `not_started` | Не розпочато | |
| `in_progress` | У процесі | |
| `submitted` | Здано, чекає оцінки | Здано, результату ще немає |
| `completed` | Зараховано | Оцінено / зараховано |
| `needs_revision` | Потребує доопрацювання | Повернули |

Незавершеними вважаються `not_started`, `in_progress`, `needs_revision`.

## Етапи

### Етап 1 — зроблено

- Семестри з датами сесії (один поточний).
- Предмети: код, викладач, контакти, форма контролю (екзамен / залік / диф. залік),
  вимоги до оцінювання, вимоги до допуску, нотатки.
- Завдання: предмет, опис, дедлайн, статус, пріоритет, як здавати, результат, чекліст,
  джерело, `needs_review`. Фільтри за предметом, статусом, дедлайном; пошук за текстом.
- Головна: «Що залишилося закрити до сесії» (відлік днів, по предметах), прострочене,
  найближчі дедлайни (2 тижні), здане без оцінки, що перевірити після AI, останні результати.
- CLI для AI з перевіркою дублікатів (схожість назв через `pg_trgm`).

### Етап 2 — розклад і оцінювання

**Розклад.** Регулярні заняття окремо від конкретних дат:
- `schedule_slots` — регулярне заняття: предмет, день тижня, час початку/кінця, тип
  (лекція / практика / лабораторна / інше), викладач, аудиторія або посилання, правило тижнів
  (щотижня / парні / непарні / конкретні тижні), період дії, джерело.
- `class_sessions` — конкретні дати: згенеровані з регулярного розкладу або разові;
  перенесення та скасування змінюють лише конкретну дату, а не регулярний запис.
- Перегляди: тижнева сітка (десктоп), список на день із перемиканням днів (смартфон),
  найближчі заняття на головній.
- Імпорт через AI: розпізнати, зіставити з наявними предметами, перевірити дублікати, не
  вигадувати; при частковому розпізнаванні — імпортувати лише достовірне й сказати, що неповно.
- Реального розкладу ще немає — не заповнювати вигаданими заняттями.

**Журнал оцінювання** (`assessments`): предмет і завдання (необов'язково), бал або текстовий
результат, максимум (якщо відомий), дата, коментар викладача, джерело, `needs_review`.
Не рахувати середній бал без відомих правил; відсутня оцінка ≠ нуль.

### Етап 3 — матеріали, база знань, пошук

- **Матеріали:** назва, тип, посилання, дата додавання, зв'язок із предметом / завданням / темою.
  Для повідомлень із Telegram зберігати текст, бо посилання на приватні чати часто не відкриваються.
  Оригінальні матеріали окремо від конспектів на їх основі.
- **База знань:** лекції, конспекти, теми, поняття, питання для самоперевірки, нотатки —
  з прив'язкою до предмета, теми й джерела. Без складної ієрархії та тегів.
- **Пошук** по всіх розділах (нечіткий, `pg_trgm`, бо в Postgres немає морфології для української).

### Пізніше, якщо знадобиться

- MCP-сервер для роботи з Claude.ai (зокрема з телефона).

## Не робимо

- Вбудований AI-чат, історію змін, складну систему розрахунку оцінок, автоматичний імпорт
  з усіх сервісів, складні теги й категорії, вигадані дані в інтерфейсі.

## UX

Спокійний функціональний інтерфейс: мінімум візуального шуму, чітка ієрархія, приглушені
кольори статусів, адаптивність (смартфон — список, десктоп — сітка), порожні стани з підказками,
усе додане AI можна виправити у формі.
